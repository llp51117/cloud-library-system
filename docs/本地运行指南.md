# 云图书管理系统 — 本地运行指南

> 本文档面向第一次在本地启动本项目的同学，按顺序执行即可跑通。
> 文中标注「实测」的内容，是在开发机上真实执行验证过的结论。

---

## 一、环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | 17 及以上 | `pom.xml` 中 `<java.version>17</java.version>`，Maven 以 `release 17` 编译 |
| Maven | 3.6+ | **本机不装也行**，项目自带 `mvnw.cmd` 包装器会自动下载 |
| Node.js | 18+ | 前端基于 Vite 5，需 Node 18 及以上 |
| MySQL | 8.0+ | 业务数据存储 |
| Redis | 7.0+ | **可选**，未安装可正常启动（见 3.1） |

### 已验证的环境事实（实测）

- `JAVA_HOME` 指向 JDK 18.0.1.1，编译通过；但 `PATH` 上的 `java` 是 JDK 24。
- **不要用 JDK 24 执行 Maven 构建**：项目依赖的 Lombok 1.18.32 不支持 JDK 24，会直接编译报错。
  构建时请确保 `JAVA_HOME` 指向 JDK 17/18/21。
- `mvn` 命令未加入 `PATH`，统一使用项目根目录的 `mvnw.cmd`。
- MySQL 9.2 已作为 Windows 服务 `MySQL92` 运行，端口 3306 可连通。
- Redis 未安装，6379 端口不通 —— 不影响启动。
- 前端目录当前**没有 `node_modules`**，首次运行必须先 `npm install`。

## 二、必做配置

### 2.1 修改数据库连接密码

文件：`src/main/resources/application.yml`（第 11-15 行）

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/cloud_library?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: 123456      # ← 必须改成你本机 MySQL 的真实密码
```

> ⚠️ 实测用 `root / 123456` 连接本机 MySQL 会返回 `ERROR 1045 (28000): Access denied`。
> 如果不改这一项，后端启动时 HikariCP 连接池校验失败，**应用直接启动不起来**。

**推荐做法**：不要往配置里写 root 密码，而是建一个专用账号：

```sql
CREATE USER IF NOT EXISTS 'cloud_library'@'localhost' IDENTIFIED BY 'cloud_library_2026';
GRANT ALL PRIVILEGES ON cloud_library.* TO 'cloud_library'@'localhost';
FLUSH PRIVILEGES;
```

然后把 `username` / `password` 改为 `cloud_library` / `cloud_library_2026`。

### 2.2 创建数据库并初始化表结构

项目已提供初始化脚本：**`sql/init.sql`**

脚本内容包含：

- 创建数据库 `cloud_library`（utf8mb4）
- 按设计文档 6.1.2 建 **10 张表**：`user`、`book`、`borrow`、`reservation`、`favorite`、`comment`、`feedback`、`notification`、`verification_code`、`announcement`
- 索引 + 外键约束（订单/收藏/评论/预约等与 `user`、`book` 的外键关系）
- 初始化数据：2 个账号 + 8 本示例图书 + 1 条公告

**执行方式 A：命令行（PowerShell）**

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.2\bin\mysql.exe" --default-character-set=utf8mb4 -u root -p -e "source D:/cloud-library-system/sql/init.sql"
```

> 注意：PowerShell 不支持 `<` 重定向，所以用 `-e "source <绝对路径>"` 的方式执行；
> 路径中的反斜杠建议改写成正斜杠，避免转义问题。
> 下文所有示例路径均假设项目位于 `D:\cloud-library-system`，若放在其他位置请自行替换。

**执行方式 B：图形化工具（推荐，最省事）**

用 Navicat / DataGrip / IDEA 打开 `sql/init.sql`，选择数据库连接后整体执行。

> ⚠️ 脚本开头有 `DROP TABLE IF EXISTS` 语句，**如果库中已有同名表的数据，请先备份**。

执行完成后可用下面语句验证：

```sql
USE cloud_library;
SELECT COUNT(*) FROM `user`;          -- 期望 2
SELECT COUNT(*) FROM `book`;          -- 期望 8
SELECT COUNT(*) FROM `announcement`;  -- 期望 1
```

**内置账号**

| 角色 | 登录邮箱 | 密码 | 说明 |
| --- | --- | --- | --- |
| 管理员 | `admin@library.com` | `admin123` | 可进入管理端全部 6 个 Tab |
| 普通用户 | `user@library.com` | `123456` | 用于借阅、收藏、评论等功能演示 |

> 两个密码均为真实 BCrypt 密文（由项目同版本 `spring-security-crypto 6.2.4` 生成），可直接登录，无需再注册。

## 三、可选配置

### 3.1 Redis（可以不装）

`RedisUtil` 的所有方法都做了 `try/catch` 兜底，Redis 连不上时只会打印警告日志并自动降级：

```
Redis 读取失败(已降级): key=xxx, err=...
```

影响范围：验证码校验会回落到数据库表 `verification_code`，功能不受影响；只是缓存加速失效。

若要安装，Windows 下可用 [Memurai](https://www.memurai.com/) 或 WSL 中安装 Redis。装好后**无需修改配置**（默认 `localhost:6379`、无密码）。

### 3.2 邮件服务（默认关闭，本地开发建议保持关闭）

`cloud-library.email.enabled: false` 时，注册/找回密码的验证码会**直接打印在后端控制台**，本地联调最方便，无需任何配置。

如需真实发信，修改 `application.yml`：

```yaml
spring:
  mail:
    host: smtp.qq.com
    port: 465
    username: 你的邮箱@qq.com
    password: 你的SMTP授权码      # 注意：是授权码，不是 QQ 登录密码

cloud-library:
  email:
    enabled: true                 # ← 改为 true
    from-name: 云图书管理系统
```

> SMTP 授权码需在 QQ 邮箱「设置 → 账户 → POP3/SMTP服务」中开启后获取。

### 3.3 大模型 API Key（默认关闭，走本地降级）

`cloud-library.ai.enabled: false` 且 `api-key: ""` 时，以下功能全部使用**本地降级实现**，可正常演示：

| 功能 | 降级后的行为 |
| --- | --- |
| 智能问答 | 基于本地知识库的规则匹配回答 |
| 语义搜索 | 关键词匹配 + 热度排序（不调用 Embedding） |
| AI 图书摘要 | 截取原简介前若干字 |
| AI 分析报告 | 本地规则引擎拼接统计结论（报告末尾会注明「未接入大模型」） |

要接入真实大模型（默认通义千问，OpenAI 兼容协议）：

```yaml
cloud-library:
  ai:
    enabled: true
    api-key: sk-你的APIKey
    base-url: https://dashscope.aliyuncs.com/compatible-mode/v1
    model: qwen-plus
    timeout-seconds: 30
```

> `embedding-base-url` 与 `embedding-model` 留空即可，语义搜索会自动降级为关键词检索。
> 千问 embedding 需单独开通，开通后填写对应的 `embedding-base-url` 与 `embedding-model` 即可启用向量检索。

### 3.4 向量数据库 Milvus（无需配置，保持关闭）

`cloud-library.vector.*` 这一组配置**在当前代码中未被引用**。

`AiService.semanticSearch` 的真实实现是「实时调用 Embedding 接口 + 在内存中计算余弦相似度」，并未接入 Milvus，因此：

- 不部署 Milvus 也能正常使用语义搜索；
- 该配置段请**保持 `enabled: false`**，不要误以为它是必填项。

> 如果后续要真正接入 Milvus，需要补充向量写入/检索代码，当前属于未实现的预留配置。

### 3.5 JWT 密钥（交作业前建议修改）

```yaml
cloud-library:
  jwt:
    secret: cloud-library-system-jwt-secret-key-2026-group1-please-change-in-production-env
    expire-hours: 24
```

本地运行无需改动，但密钥中已写明 `please-change-in-production-env`，正式部署前请替换为随机字符串。

## 四、启动步骤

### 4.1 启动后端

```powershell
cd "D:\cloud-library-system"
.\mvnw.cmd spring-boot:run
```

首次执行会自动下载 Maven 与依赖，耗时较长属正常现象。

看到类似以下日志即为启动成功：

```
Started CloudLibrarySystemApplication in x.xxx seconds
Tomcat started on port(s): 8080 (http)
```

后端地址：`http://localhost:8080`

### 4.2 启动前端

```powershell
cd "D:\cloud-library-system\frontend"
npm install
npm run dev
```

浏览器会自动打开 `http://localhost:5173`（`vite.config.js` 中配置了 `open: true`）。

> 当前 `frontend/` 下没有 `node_modules`，**必须先执行 `npm install`**，否则 `npm run dev` 会报找不到 `vite`。

跨域与接口代理已在 `frontend/vite.config.js` 中配置完毕，无需额外设置：

```js
proxy: {
  '/api':     { target: 'http://localhost:8080', changeOrigin: true },
  '/uploads': { target: 'http://localhost:8080', changeOrigin: true }
}
```

前端 Axios 实例的 `baseURL` 为 `/api`，因此通过 Vite 代理访问后端，不存在跨域问题。

## 五、验证清单

按顺序逐项确认：

1. **后端启动无异常** —— 控制台无 `Access denied` / `Communications link failure` 等报错。
2. **前端页面能打开** —— `http://localhost:5173` 正常渲染，不是白屏。
3. **能拿到验证码（无需邮件服务）** —— 点击「注册 / 忘记密码」，验证码应打印在后端控制台。
4. **管理员登录** —— 使用 `admin@library.com / admin123` 登录成功。
5. **管理端 6 个 Tab 均可访问** —— 数据概览、图书管理、用户管理、借阅管理、评论管理、通知公告，逐个点开确认不白屏。
6. **用户端核心流程** —— 用 `user@library.com / 123456` 登录，测试图书浏览、搜索、收藏、借阅、评论、预约。
7. **图片上传** —— 上传头像或图书封面，确认能正常回显（首次上传会自动创建 `uploads/` 目录）。

## 六、常见问题排查

### 6.1 后端启动即失败

| 报错信息 | 原因 | 解决 |
| --- | --- | --- |
| `ERROR 1045 Access denied for user 'root'` | 数据库密码错误 | 按 2.1 改为本机真实密码 |
| `Communications link failure` | MySQL 未启动 | 启动 `MySQL92` 服务：`net start MySQL92` |
| `Unknown database 'cloud_library'` | 数据库未创建 | 按 2.2 执行 `sql/init.sql` |
| `Table 'cloud_library.xxx' doesn't exist` | 建表脚本未执行或执行不全 | 重新完整执行 `sql/init.sql` |
| `Port 8080 was already in use` | 端口被占用 | 杀掉占用进程，或改 `server.port` |

### 6.2 Maven 编译报 Lombok 相关错误

```
java.lang.NoClassDefFoundError: com/sun/tools/javac/...
```

原因：用 JDK 24 执行了构建，而 Lombok 1.18.32 不支持该版本。

解决：将 `JAVA_HOME` 指向 JDK 17/18/21 后重新构建，例如：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-18.0.1.1"
.\mvnw.cmd clean compile
```

> 项目此前存在一处编译错误（`AiService.java` 第 370 行未捕获 `JsonProcessingException`），已修复，当前 `mvnw clean compile` 为 `BUILD SUCCESS`。

### 6.3 前端启动报错

| 报错信息 | 原因 | 解决 |
| --- | --- | --- |
| `'vite' 不是内部或外部命令` | 未装依赖 | 执行 `npm install` |
| 页面能打开但接口全部 404 | 后端未启动 | 先启动后端（8080） |
| 请求报 CORS 错误 | 未走 Vite 代理 | 确认访问的是 `5173` 端口，而非直接访问 8080 |

### 6.4 控制台出现 Redis 警告

```
Redis 写入失败(已降级): key=...
```

这是**正常现象**，属于预期内的自动降级，无需处理。若不想看到该日志，安装并启动 Redis 即可。

### 6.5 上传的图片访问 404

- 确认后端已启动，且 `uploads/` 目录生成在**后端进程的工作目录**下；
- `application.yml` 中 `cloud-library.upload.path: ./uploads/` 是相对路径，切换启动目录后会指向不同位置；
- 该目录已由 `WebMvcConfig` 映射到 `/uploads/**`，无需手动创建。
