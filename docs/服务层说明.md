## 一、基础设施类

### AuthService 用户认证

用户注册、登录、验证码、找回密码。验证码有效期 5 分钟，Redis 不可用时自动降级为仅数据库校验。

| 方法 | 说明 |
| --- | --- |
| `register(dto)` | 校验两次密码一致 → 邮箱查重 → BCrypt 加密入库（默认 `role=0`、`status=1`、`banDays=0`） |
| `login(dto)` | 邮箱/密码校验；`status=0` 拒绝登录；`status=2` 时若 `isBanExpired` 到期则自动恢复为正常再放行；签发 JWT 返回 `LoginVO(token, UserVO)` |
| `sendCode(email, type)` | `type` 0=注册 / 1=找回密码，双向校验邮箱存在性 → 生成 6 位码；先删旧码再写 `verification_code` 表，同时写 Redis，最后调用 `MailService` |
| `resetPassword(dto)` | 校验两次新密码 → `verifyCode(type=1)` → 更新密码并清理验证码 |
| `verifyCode(email, code, type)` | 先查 Redis，再查数据库最新一条，分别处理「未获取 / 已过期 / 错误」 |
| `isBanExpired(user)` | 私有方法，判断 `banStartTime + banDays` 是否早于当前时间 |

> 说明：禁用到期恢复是**登录时惰性判断**，并非定时任务。

### MailService 邮件

发送验证码邮件与通知邮件，统一加 `【云图书管理系统】` 前缀。

| 方法 | 说明 |
| --- | --- |
| `sendVerificationCode(to, code, type)` | 按类型生成注册 / 找回密码邮件正文（含 5 分钟有效提示） |
| `sendNotify(to, subject, content)` | 通用通知邮件 |
| `send(to, subject, content)` | 私有方法；`cloud-library.email.enabled=false` 时**只打印控制台并返回**，方便本地开发；发送异常仅记日志不抛出 |

### FileService 文件上传

图片上传，本地存储。限制：10MB 以内，扩展名白名单 `jpg/jpeg/png/gif/webp/bmp`。

| 方法 | 说明 |
| --- | --- |
| `uploadImage(file, subDir)` | 空文件校验 → 大小校验 → 扩展名校验 → 按 `subDir/yyyyMMdd` 建目录 → UUID 重命名落盘 → 返回 `urlPrefix + dirName + fileName` |

### ExcelService Excel 导入导出

基于 POI 的图书批量导入模板生成与解析，无状态服务。

| 方法 | 说明 |
| --- | --- |
| `writeBookTemplate(outputStream)` | 写出图书导入模板（表头 + 「三体」示例行，简介列加宽） |
| `parseBooks(inputStream)` | 从第 2 行起解析，书名/作者为空则跳过，价格按 `BigDecimal` 容错；无有效数据抛异常 |
| `getString(cell)` | 私有方法，兼容 NUMERIC（整数值去掉小数）/ BOOLEAN / STRING 三种单元格类型 |

## 二、业务服务类

### NotificationService 个人通知

通知类型常量：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `TYPE_ANNOUNCEMENT` | 0 | 系统公告 |
| `TYPE_BORROW_SUCCESS` | 1 | 借阅成功 |
| `TYPE_RESERVATION_READY` | 2 | 预约轮到 |
| `TYPE_RESERVATION_TIMEOUT` | 3 | 预约超时 |
| `TYPE_RETURN_SUCCESS` | 4 | 还书成功 |
| `TYPE_OVERDUE` | 5 | 逾期提醒 |
| `TYPE_FEEDBACK_REPLY` | 6 | 反馈回复 |
| `TYPE_REMIND_RETURN` | 7 | 催还提醒 |

| 方法 | 说明 |
| --- | --- |
| `send(userId, type, title, content)` | `userId` 为 null 直接跳过；插入未读通知 |
| `myNotifications(userId, page, size, type)` | 分页 + 可选类型过滤 + 时间倒序 |
| `unreadCount(userId)` | 未读条数 |
| `markRead(id, userId)` | 校验归属后置已读，非本人静默返回 |
| `markAllRead(userId)` | 通过 Mapper 批量置已读 |

### AnnouncementService 公告

| 方法 | 说明 |
| --- | --- |
| `listActive()` | 用户端：查询有效公告列表 |
| `listAll()` | 管理端：查询全部公告（含已删除） |
| `detail(id)` | 公告详情，不存在抛异常 |
| `publish(dto, adminId)` | 发布公告（`status=1`），返回 id |
| `update(dto)` | 需携带 id；仅对非空标题/正文做局部更新 |
| `delete(id)` | 逻辑删除（`status=0`） |

### FavoriteService 收藏

| 方法 | 说明 |
| --- | --- |
| `toggle(userId, bookId)` | 图书须存在；已收藏则删除并 `favoriteCount - 1` 返回 `false`，未收藏则插入并 `+1` 返回 `true` |
| `myFavorites(userId)` | 我的收藏列表（带图书信息） |
| `isFavorited(userId, bookId)` | 是否收藏；`userId` 为 null 返回 `false` |

### CommentService 评论与审核

评论状态：`0` 正常 / `1` 系统删除 / `2` 管理员删除 / `3` 管理员恢复。
内置敏感词库：广告、代购、赌博、诈骗、色情、暴力、刷单、加微信、私聊、违禁。

| 方法 | 说明 |
| --- | --- |
| `listByBook(bookId, page, size)` | 用户端：某本图书的评论分页 |
| `add(userId, dto)` | 图书须存在；命中敏感词自动置 `status=1` |
| `like(commentId)` | 通过 Mapper `increaseLike` 后返回最新点赞数 |
| `report(commentId)` | 「@管理员」举报标记 `isReported=1` |
| `adminPage(tab, page, size)` | `all`=正常+已恢复 / `system`=系统已删 / `reported`=被举报；并回填删除原因、举报原因 |
| `adminDelete(commentId)` | 管理端删除（`status=2`） |
| `adminRestore(commentId)` | 恢复评论（`status=3` 并清空举报标记） |
| `containsSensitiveWord(content)` | 私有方法，转小写后包含匹配 |

### FeedbackService 意见反馈

反馈类型名：功能建议 / 举报用户 / 内容错误 / 系统BUG / 其他。

| 方法 | 说明 |
| --- | --- |
| `submit(userId, dto)` | 提交反馈，插入 `status=0`，返回 id |
| `myFeedbacks(userId)` | 我的反馈列表 |
| `adminPage(page, size, status)` | 管理端分页：`0` 待回复 / `1` 已回复 / `null` 全部 |
| `reply(feedbackId, reply)` | 写入回复与回复时间，置 `status=1`，并按类型名向用户发送 `TYPE_FEEDBACK_REPLY` 通知 |

### ReservationService 预约

预约状态：`0` 排队中 / `1` 可借阅 / `2` 已借阅 / `3` 用户取消 / `4` 超时取消。

| 方法 | 说明 |
| --- | --- |
| `reserve(userId, bookId)` | 仅在图书已被借出时允许，否则提示可直接借阅；实际转调 `borrowService.joinQueue` |
| `myReservations(userId)` | `status=0` 回填 `queuePosition`；`status=1` 按 `availableTime` 计算 `remainHours` |
| `cancel(userId, reservationId)` | 状态 `2/3/4` 分别拦截；若取消的是「可借阅」状态则顺延给下一位 |
| `borrowByReservation(userId, reservationId)` | 仅 `status=1` 可借；超出 `keepHours` 报「已超时」；调 `createBorrowRecord` 后置 `status=2` |
| `handleTimeout()` | 定时任务用，批量把超时预约置 `status=4`、发超时通知并顺延，返回处理条数 |
| `hasActiveReservation(userId, bookId)` | 是否存在 `status in (0,1)` 的有效预约 |
| `passToNext(bookId)` | 私有方法，取队列第一位置 `status=1`、`availableTime=now` 并发「可借阅」通知 |
| `queuePosition(bookId, userId)` | 私有方法，遍历预约队列定位序号 |

### BorrowService 借阅

借阅状态：`0` 借阅中 / `1` 已归还 / `2` 逾期。

**用户端**

| 方法 | 说明 |
| --- | --- |
| `borrow(userId, bookId)` | 账号禁用拦截 → 不能重复借同一本 → 若已被他人预约到号或已被借出，自动转 `joinQueue` 并返回排位提示；否则直接借阅 |
| `joinQueue(userId, bookId)` | 重复预约拦截 → 插入 `status=0` → 发「预约成功」通知 → 回填 `queuePosition` |
| `createBorrowRecord(userId, bookId)` | 已被借出则拒绝；`borrowDate=now`、`dueDate=now+borrow.days`、`renewCount=0`；`increaseBorrowCount` 并发借阅成功通知（供预约「去借阅」复用） |
| `myBorrows(userId, page, size, status)` | 先 `refreshOverdue()` 再分页 |
| `returnBook(userId, borrowId)` | 归属校验 + 已归还拦截 → `doReturn(borrow)`（**已归还状态只由用户在用户端触发**） |
| `renew(userId, borrowId)` | 校验续借次数上限、距应还日 `renewBeforeDays` 限制、存在排队（`status=0`）禁止续借；延长 `renewDays` 并通知 |

**管理端**

| 方法 | 说明 |
| --- | --- |
| `adminPage(page, size, status, searchType, keyword)` | `searchType` 支持 `user` 按用户 / `book` 按图书 / `platform` 按平台 |
| `remind(borrowId)` | 手动催还（单条），发 `TYPE_REMIND_RETURN` 通知 |
| `remindAll()` | 一键催还，取「已逾期 + 3 天内到期」列表批量发通知，返回条数（~~`forceReturn` 强制归还已下线~~） |
| `autoRemind(beforeDays)` | 定时任务用，取「即将到期」列表，按是否逾期分别发逾期 / 即将到期通知，返回条数 |

**内部与对外公开的辅助方法**

| 方法 | 说明 |
| --- | --- |
| `doReturn(borrow)` | 私有方法，置 `status=1` + `returnDate` + `returnType=0` → 发归还成功通知 → 唤醒队伍第一位（`status=1` + `availableTime` + 通知） |
| `refreshOverdue()` | 把 `status=0` 且 `dueDate < now` 的记录批量置 `2` |
| `isBookBorrowed(bookId)` | 存在 `status in (0,2)` 即视为借出 |
| `findReadyReservation(bookId)` | 取 `status=1`（已到号）且最早的一条 |
| `findWaitingReservation(bookId)` | 取 `status=0`（排队中）且最早的一条 |
| `queuePosition(bookId, userId)` | 私有方法，计算排队位次 |

**内部方法**

### AiService AI 能力

当 `cloud-library.ai.enabled=true` 且配置了 API Key 时调用真实大模型（OpenAI 兼容协议，默认通义千问 compatible-mode）；否则自动降级为本地知识库规则回答，保证系统可离线运行。

**1. 智能问答（RAG）**

| 方法 | 说明 |
| --- | --- |
| `chat(question)` | 先判意图（CASUAL / RULE / BOOK / GENERAL）→ 闲聊走自然回应、规则类答借阅规则、图书类 `retrieveKnowledge(question, 5)` 检索后推荐、通用类交大模型自由回答；失败/未启用则走本地回复池；返回 `ChatVO(answer, references, aiGenerated)` |
| `retrieveKnowledge(question, limit)` | 私有方法，`extractKeywords` → `searchByKeywords`，失败兜底返回全量前 N |
| `buildRagPrompt(question, related)` | 私有方法，注入图书知识库 + 借阅规则（10 天 / 续借 1 次 15 天 / 24 小时内借阅） |
| `buildLocalAnswer(question, related)` | 私有方法，按「借/还」「预约/排队」关键词给出规则说明 + 检索结果列表 |

**2. 语义搜索（Embedding 向量相似度）**

| 方法 | 说明 |
| --- | --- |
| `semanticSearch(query, limit)` | 全量图书逐条 `embed` 后按 `cosine` 排序取 Top-N；未启用/失败降级为 `searchByKeywords` |
| `embed(text)` | 调用 `/embeddings` 接口，任何异常返回 `null` |

**3. AI 摘要**

| 方法 | 说明 |
| --- | --- |
| `generateBookSummary(title, author, description)` | 大模型生成 80 字内摘要，失败时用本地模板（附「本地自动生成」标识） |

**4. AI 分析报告**

| 方法 | 说明 |
| --- | --- |
| `generateAnalysisReport(statistics, hotBooks, trend)` | 构造 4 段式分析 Prompt；失败走 `buildLocalReport` |
| `buildStatisticsText(...)` | 私有方法，把统计数据拼成文本 |
| `buildLocalReport(...)` | 私有方法，输出「整体情况 / 热门图书 / 借阅趋势 / 运营建议」，趋势段落计算总次数与日均 |

**工具方法**

| 方法 | 说明 |
| --- | --- |
| `callChatModel(prompt)` | 私有方法，调用 OpenAI 兼容 `/chat/completions`，解析 `choices[0].message.content` |
| `jsonHeaders()` | 私有方法，构造 JSON + Bearer 鉴权请求头 |
| `isAiEnabled()` | 私有方法，降级开关：需 `ai.enabled=true` 且配置了 apiKey |
| `cosine(a, b)` | 私有方法，余弦相似度 |
| `extractKeywords(text)` | 公开方法，去标点 + 停用词表 + 去重 |
| `trim(text, length)` | 私有方法，压缩空白并按长度截断加省略号 |

## 三、服务间依赖关系

```
AuthService        → MailService, JwtUtils, RedisUtil, UserMapper, VerificationCodeMapper
UserService        → AuthService, MailService, UserMapper
BorrowService      → NotificationService, BookMapper, BorrowMapper, ReservationMapper, UserMapper
ReservationService → BorrowService, NotificationService, BookMapper, ReservationMapper
BookService        → AiService, FavoriteService, BorrowService, 各 Mapper
FavoriteService    → BookMapper, FavoriteMapper
CommentService     → BookMapper, CommentMapper
FeedbackService    → NotificationService, FeedbackMapper
StatisticsService  → AiService, BookMapper, UserMapper, BorrowMapper
AiService          → BookMapper, RestTemplate, CloudLibraryProperties
FileService        → CloudLibraryProperties
ExcelService       → （无依赖，纯工具）
MailService        → JavaMailSender, CloudLibraryProperties
AnnouncementService→ AnnouncementMapper
NotificationService→ NotificationMapper
```

需要注意的两处**双向依赖**：

- `BorrowService` ↔ `ReservationService`（预约要 `borrowService.joinQueue` / `findWaitingReservation`，借阅要直接操作 `reservationMapper`）
- `BookService` ↔ `FavoriteService` / `BorrowService` / `AiService`（`BookService` 调它们，而 `AiService` 又依赖 `BookMapper`）

## 四、定时任务

定时任务不在 `service` 包内，由 `com.group1.cloudlibrary.schedule.ScheduledTask` 驱动：

| 触发时间 | 任务 | 调用的服务方法 |
| --- | --- | --- |
| 每天 09:00（`0 0 9 * * ?`） | 自动催还 + 逾期标记 | `borrowService.autoRemind(3)` |
| 每 10 分钟（`0 */10 * * * ?`） | 预约超时顺延 | `reservationService.handleTimeout()` |
| 每天 02:00（`0 0 2 * * ?`） | 清理过期验证码 | `verificationCodeMapper.cleanExpired()` |

## 五、关键业务规则速查

| 规则 | 取值 | 来源 |
| --- | --- | --- |
| 借阅期 | 10 天 | `cloud-library.borrow.days` |
| 续借次数上限 | 1 次 | `cloud-library.borrow.renew-limit` |
| 续借延长天数 | 15 天 | `cloud-library.borrow.renew-days` |
| 可续借时间窗口 | 应还日前 3 天内 | `cloud-library.borrow.renew-before-days` |
| 预约保留时长 | 24 小时 | `cloud-library.reservation.keep-hours` |
